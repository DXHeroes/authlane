## API Keys

Authlane uses API keys for authentication. Include your API key in the `Authorization` header:

```bash
Authorization: Bearer sk_live_YOUR_API_KEY
```

## Creating API Keys

### Via Dashboard

1. Log in to [dashboard](https://app.authlane.com)
2. Go to **Settings** → **API Keys**
3. Click **Create API Key**
4. Name your key and select type
5. Copy the key (shown once!)

### Via API

```bash
curl -X POST https://api.authlane.com/api/v1/admin/api-keys \
  -H "Authorization: Bearer YOUR_ADMIN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "tenantId": "tenant_123",
    "name": "Production API Key",
    "type": "live"
  }'
```

## API Key Security

<Warning>
  Never expose API keys in client-side code or commit them to version control!
</Warning>

### Best Practices

1. **Use environment variables**
   ```bash
   export AUTHLANE_API_KEY=sk_live_...
   ```

2. **Rotate keys regularly**
   - Every 90 days minimum
   - Immediately after suspected compromise

3. **Use different keys per environment**
   - Development: `sk_test_...`
   - Production: `sk_live_...`

4. **Revoke unused keys**
   ```bash
   curl -X DELETE https://api.authlane.com/api/v1/admin/api-keys/key_abc \
     -H "Authorization: Bearer YOUR_ADMIN_API_KEY"
   ```

## Permissions

API keys inherit permissions from their tenant:

| Resource | Live Key | Test Key | Admin Key |
|----------|----------|----------|-----------|
| Connections | ✅ Read/Write | ✅ Sandbox | ✅ All Tenants |
| Services | ✅ Read | ✅ Read | ✅ Read/Write |
| OAuth | ✅ Execute | ✅ Execute | ✅ Execute |
| API Keys | ❌ | ❌ | ✅ Manage |
| Tenants | ❌ | ❌ | ✅ Manage |

## Testing Authentication

```bash
curl https://api.authlane.com/api/v1/services \
  -H "Authorization: Bearer sk_live_..."
```

**Success (200):**
```json
{
  "data": [...]
}
```

**Failure (401):**
```json
{
  "error": {
    "code": "invalid_api_key",
    "message": "The API key provided is invalid"
  }
}
```
